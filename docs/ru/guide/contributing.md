# Участие в разработке

## Стиль кода

- **Go**: Следуйте [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments)
- **TypeScript/React**: Следуйте правилам ESLint
- Используйте `gofmt` и `prettier` для форматирования

## Формат сообщений коммитов

```
<type>(<scope>): <subject>

<body>
```

Типы: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`

## Стратегия ветвления

- `main`: Стабильные релизы
- `develop`: Ветка разработки
- `feature/*`: Ветки функций
- `fix/*`: Исправления ошибок

## Процесс Pull Request

1. Сделайте форк репозитория
2. Создайте ветку функции: `git checkout -b feature/your-feature`
3. Зафиксируйте изменения
4. Запустите тесты: `make test`
5. Создайте Pull Request

## Ревью кода

Все PR требуют как минимум одного ревью от мейнтейнера. Основные области внимания:
- Безопасность памяти
- Безопасность конкурентности (корректность блокировок)
- Полнота обработки ошибок
- Совместимость API
